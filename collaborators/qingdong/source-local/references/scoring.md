# 隔离评分量表

检索子 Agent 读。按人对照当前需求版本和该人简历打分，人与人之间不互相参照。相关经验按简历工作或项目起止时间计算，重叠时段只计一次，信息不足记待核实；不用候选人年龄或毕业年份反推年限。

## 每人一条 candidate_scores

字段只有这些：

| 字段 | 内容 |
| --- | --- |
| `candidate_ref` / `path` / `file_path` / `locator` | 与 `judged` 里同一人一致；重评照抄原记录 |
| `scored_iteration` | 本轮 N；重评照抄原记录 |
| `card` | `{name, company, title, education, years, city}`，取自简历，没写的填 null |
| `matches` | 没有硬冲突为 true |
| `must_score` | 0–100 整数 |
| `nice_score` / `risk_score` | 0–100 整数；需求版本没有加分项 / 排除信号时为 null |
| `must_unknown` | 有必须满足项在简历里找不到依据时为 true |
| `unknown` | 找不到依据的条目，最多 20 项、每项 200 字内；`must_unknown=true` 时至少一项 |
| `evidence_summary` | 800 字内的推荐或不推荐理由，不是履历复述；引用原文时带页码或 sheet 行号 |
| `short_reason` | 40 字内一句话，给报告的「未推荐原因」聚合用，如「缺 Agent 落地经历」 |
| `correction_reason` | 仅重评时写 |

总分、可推荐、强匹配、Top 10 由 ledger.py 从这些原始分重算。

## 硬冲突

只有简历原文明确抵触某条明确的硬性筛选条件或排除信号，才构成硬冲突，必须引用原文。信息缺失、证据弱、能力差距、低分都是评分问题，不是硬冲突。

有硬冲突 = **不符合**（`matches=false`）；没有 = **符合**。符合只是准入，推荐由总分决定。

## 分项与总分

1. **必须满足匹配分**（0–100）：对照必须满足与硬性筛选条件。90–100 高度匹配，80–89 强匹配，70–79 基本匹配，60–69 弱、存在实质缺口，低于 60 不推荐。
2. **加分项匹配分**（0–100）：需求版本里有加分项才评，否则记 null。分段同上。
3. **风险分**（0–100）：需求版本里有排除信号才评，否则记 null。0 无明确风险，1–29 低，30–59 实质，60–79 高，80–100 严重。
4. **总分** = 必须满足 × 60% + 加分项 × 25% + (100 − 风险) × 15%；为 null 的维度剔除后按剩余权重重新归一化，四舍五入到整数。

每条得分引用明确原文，优先查需求条目的 `evidence_section` 对应的简历区块，也可取自其他区块；取证位置不改变条件的满足标准。全文仍无依据时记 **unknown**：既不给分也不算否定，逐项列进 `unknown`；计算必须满足匹配分时把 unknown 的条目从分母里剔除，只按有证据（正面或反面）的条目算。需求版本里的 `verify_in_interview` 不参与任何分项，简历上碰巧写了也只作加分项证据。

Excel 台账一行通常只有几列摘要，写不出的经历照样记 unknown，不因为材料短就压低分数。

## 判定口径

- **可推荐** = 符合且总分 ≥ 60。
- **强匹配** = 符合、总分 ≥ 80、必须满足 ≥ 70、风险为 null 或 ≤ 30，且必须满足项均已核实（`must_unknown=false`）；加分项 unknown 不影响此门槛。

性别、学校名称、民族、婚育不参与任何分项。
