### 2026-09-23 · 新增本地简历库寻访 `wts-local`

#### 改了什么

- 新增 `source-local/`：Skill 名 `wts-local`，从本机已整理的简历和 Excel 台账里找人，用宿主工具 `search_local_resumes`，不用猎聘、不用浏览器。
- 检索策略沿用 `wts`，没有改：主锚点 + 支持词 + 公司词、两路（利用 / 探索）、每轮主路径 5 人、第二路 3 人、补搜、已看台账、第 1 轮尺度确认、轮内扩张门、PRF 先试后晋升、反思只有建议权、Controller、评分公式、强池、终态报告、方向选择。
- 所有查询都用 `match_mode=all`，计划里的词全部都要命中，和猎聘的「与」查询一样。检索词不含空格；锚点带空格时拆开，每个词都算锚点。
- 新增**检索子 Agent**（`references/retrieval.md`）：检索、去重、硬筛、挑人、补搜、评分、PRF 都在一次运行里完成，结果写成 run 文件。主 Agent 只读 `ledger.py merge` 打印的回执，不读简历正文。
- 反思和市场求证改由主 Agent 自己做。子 Agent 只在四个节点派：每轮一次、尺度调整后重评、每次扩张、换需求版本后重评。
- 新增 `scripts/ledger.py`，代替 Builder 的确定性校验。子命令：
  - `check-plan`：校验计划契约、锚点和重复查询。
  - `merge`：写台账和评分表，重算总分、Top 10、强池和扩张门。
  - `adopt`：合并上一次寻访的台账。
  - `settle`：写报告数据。
- 硬筛不再有站内筛选，全部由子 Agent 按正文判断：明确抵触才淘汰，正文没写记 unknown。候选人身份：
  - PDF / Word 一个文件算一人。
  - Excel 一行算一人。
  - 同一人的多份材料记 `duplicate`，只评一份。
- 报告里的「详情链接」改成简历文件位置（Excel 带 sheet 和行号）。

#### 为什么改

- 宿主派子 Agent 是同步、串行、每次往返很慢的调用。原来每轮要派评分、PRF、反思三个子 Agent，现在合成一个，每轮常规只派一次。
- 简历正文留在子 Agent 上下文里，主 Agent 的上下文只放回执和一行一人的卡片。
- 原来的 Builder 负责确定性校验（总分、Top 10、重复查询、需求版本一致）。本地库没有 Builder，所以把这些交给 `ledger.py`，避免数字来自模型心算。

#### 需要重点测试

- 本机没有整理简历时，第 1 轮子 Agent 返回 `library_not_configured`，主 Agent 提示用户去「整理简历」→「添加文件夹」或「添加Excel简历表」，然后停止。
- 某个查询 `NO_MATCHES` 时照常进入后续步骤，不提示用户去整理简历。
- 每次检索都是 `match_mode=all`；两次检索之间至少隔 1 秒；翻页只用 `next_offset`，每路不超过 30 条；同一组参数不重复发。
- 带公司词、可评人数不足 5 时，子 Agent 在同一次运行里补搜，回执 `refill` 非空，公司池标「人不够」；下一轮计划重复补搜的词组合会被 `check-plan` 拒绝。
- Excel 同一个文件里不同行的人各自算一人；同一人的 PDF 和 Excel 行只评一份。
- 扩张子 Agent 按 `remaining` 里的 `file_path` 读原文，不发新检索。
- 尺度调整或换需求版本后派 rescore，`settle` 在有人未重评时拒绝。
- 主 Agent 的上下文里不出现简历正文；播报里不出现 run、brief、candidate_ref 等字段名。
- 宿主需要支持两件事：子 Agent 按 `file_path` 读 PDF / Word / Excel 原文，主 Agent 运行 Python 脚本。

#### 同批次的策略与可读性改动（只改 SKILL.md 和 references，不涉及 Builder）

- **简历可见性测试与面试核实项**（步骤 2、`requirements-draft.md`、`scoring.md`、`final-report.md`）：通过反事实测试的每条要求再问"猎聘详情的哪个区块能看出来"，答不出来的（顶会论文、绩效、口碑、抗压等）进新桶 `verify_in_interview`，不删除、不评分、不筛选，画像和终态报告里单列提醒用户面试核实。必须满足分只按有证据的条目算，unknown 从分母剔除。
- **岗位经验澄清**：确认岗位实际需要的经验、职级或薪资条件；年限按简历实际经历计算，重叠时段只计一次，信息不足待核实。删除年龄映射年限的示例，避免把年限作为年龄筛选的替代。

#### 为什么改

- 顶会等简历不会写的条件被放进评分后，要么把人误杀，要么被模型自作主张删掉；现在给它一个明确去处。
- 年龄无法可靠推算工作年限；澄清实际岗位需要后，按可核实的经历判断。
- 用户反馈看不懂"证据文本""决策要求不至少""主锚点"，根因是内部名词和工具提示直接漏到了播报里。
- 现有工作流按列表顺序取前 5 / 前 3 张卡片开详情，第 2 轮的前几张往往就是第 1 轮开过的人；同一对话里第二次寻访更是完全不知道第一次看过谁。
- 猎聘首屏 30 张卡片，规则初筛后常剩二十多张；一轮只看 5 个，效果好的时候没有办法在同一页继续深挖，只能换词进下一轮。
